## Challenge

This is a sample narrative for the case-study template. It is not a record of work delivered for a real company.

A founder needs the first version of a product that more than one customer can sign in to. Accounts, permissions, and the boundary between customers are still being described in conversation.

## Solution

The sample approach would write down the tenancy rules, the first set of screens, and the API those screens depend on. Billing would be included only if the first release actually charges.

## Architecture

A web client, an API, and a database with an explicit customer boundary. The exact stack would be chosen in planning and recorded here when a real project exists.

## Features

Account sign-in, a customer workspace, and an admin view. Nothing in this list was shipped for a client.
